## Privacy invariants

- Another owner cannot list, search, read or infer a private capture. Workspace,
  brand and destination permissions are not source grants. Creator reads still
  require active membership and an admissible lifecycle state.
- Original sharing selects recipients, revision and permitted purposes explicitly.
  Recipients cannot reshare, edit the original or widen purposes. A newer source
  revision never inherits an old revision's grant without an explicit decision.
- Excerpt release requires an explicit review of the selected text and intended
  recipients/purposes. Store a separate immutable snapshot and private lineage;
  recipient DTOs contain only reviewed fields. No original metadata is inferred
  from a foreign-key join or nested API response.
- Every share/revoke/edit/erase/recovery command checks current versions. An
  in-flight request cannot re-establish a revoked grant using stale state.
  Source revocation invalidates dependent excerpt access immediately and provides
  the versioned permission boundary that later publishing/AI commands must use.
  No future worker, production AI executor or unsent publication is fabricated
  merely to test this step.
- Recovery is a separate owner-authorised command for a demonstrably orphaned
  source, with fresh authentication, an explicit active custodian and a bounded
  reason. Preserve original capturer identity and minimal audit evidence. Ordinary
  owner reads never implicitly recover data or disclose orphan text.
- Erasure immediately prevents reads and reuse, removes stored source/excerpt
  text as implemented in this unit, and records resource-scoped deletion state
  for the independent ledger/restore work in step 1.8. Do not imply that deleting
  a source withdraws content already copied or published outside Cadence.

## Data-handling record

| Data | Actors/purpose | Storage and lifetime | Revocation/deletion |
| --- | --- | --- | --- |
| Brand/playbook | Authorised workspace/brand members; editorial guidance | Private Postgres; explicit versions while retained | Brand access removal blocks further reads; no automatic source grant |
| Capture title/text/revisions | Creator or explicitly authorised original recipient for selected purpose | Private Postgres; no browser persistence; until deletion or configured expiry | Live version/purpose/lifecycle checks; erase text and restricted derivatives |
| Reviewed excerpt | Explicit selected recipients and purposes | Separate reviewed Postgres snapshot with hidden source lineage | Parent revocation/erasure blocks reads/reuse; no original-field fallback |
| Grants/audit/receipts | Restricted command services; accountability and safe retry | IDs, versions and bounded reason codes; minimal audit/receipt expiry 180 days | No plaintext capture, excerpt, invitation secret or free-form private reason in logs/receipts |
| Search input/results | Authenticated authorised caller | Bounded request and response memory, no-store; query sent in body | Permission filtering before ranking/counts/snippets; no shared content cache |

No source text enters Clerk metadata, analytics, request logs or exception reports.
Actual provider backup expiry, independent erasure replay and scheduled cleanup
remain step 1.8 acceptance, not claims made by this feature's presence.

## Verification checklist

- Two-owner privacy isolation, cross-workspace/brand IDs, viewer mutations,
  unauthorised purpose changes and removed-member denial.
- Direct SQL roles, REST/RPC and Storage cannot bypass source visibility or
  mutation entry points; old source mutation privileges are explicitly tested.
- Original grants cannot unlock later revisions; excerpt grants disclose only
  reviewed text; malicious nested IDs cannot retrieve lineage/private metadata.
- Search/count/snippet leakage tests, including another owner's secret markers.
- Concurrent edits, share/revoke races, stale versions, idempotent retries and
  permission loss between session validation and workspace lock acquisition.
- Fresh-auth recovery with active custodian and orphan proof; ordinary owner
  recovery bypass denial; minimal audited reasons and preserved capturer identity.
- Erasure removes restricted original and excerpt text and blocks reads/reuse;
  deletion-ledger scope cannot accidentally erase unrelated user material.
- No-store headers, sanitised errors/logs, no browser content persistence, and
  clearing private UI state on account/workspace change or authorisation loss.
- Desktop, iPhone 13 (390×844) and iPhone 16 Pro Max (430×932) workflows;
  keyboard, enlarged text, light/dark, reduced motion, empty/error/loading states.
- Repository formatting/lint/types/unit/build, real SQL and driver tests,
  generated-type comparison, secret scan and applicable CodeQL checks.
